# nem

nem tracks recurring household and maintenance work, and lets you record that
work by scanning a physical code attached to the thing itself.

## Language

### Work

**Task**:
A unit of recurring work with a schedule — "replace the water filter". The thing
you complete.
_Avoid_: chore, todo, item, job, routine

**Completion**:
A record that a task was performed at a particular moment.
_Avoid_: done, tick, check-off, log entry

**Due date**:
The moment a task next needs doing. Frequently in the past.
_Avoid_: next due, deadline, target date

**Overdue**:
The state of a task whose due date has passed.
_Avoid_: late, missed, outstanding

### Scheduling

**Schedule**:
The rule that determines a task's due date. Every task has exactly one, and it
is either floating or fixed.
_Avoid_: cadence, recurrence, repeat rule, frequency

**Floating schedule**:
A schedule whose due date is measured forward from the last completion.
_Avoid_: relative schedule, rolling schedule, interval schedule

**Fixed schedule**:
A schedule whose due dates come from the calendar and ignore when the work was
actually done.
_Avoid_: absolute schedule, calendar schedule, recurring event

**Occurrence**:
One dated instance generated by a fixed schedule. Floating schedules have no
occurrences.
_Avoid_: instance, repetition, event

**Missed occurrence**:
An occurrence that passed without a completion. Never surfaced as a row of its
own.
_Avoid_: skipped occurrence, backlog item

### Physical world

**Target**:
A physical place or object that work is done on — the boiler, the car, the front
door. Tasks belong to targets, and scannable codes are bound to targets.
_Avoid_: location, place, asset, thing, object, zone

**Binding**:
The association between one scannable code and one target.
_Avoid_: mapping, pairing, link, registration

**Tag**:
A physical NFC tag. Reserved for NFC hardware only.
_Avoid_: using "tag" for a category; sticker, chip, token

**Label**:
A QR code generated by nem and printed onto something.
_Avoid_: QR tag, sticker, code

**Barcode**:
A pre-existing product code (EAN, UPC, Code 128) that nem binds but did not
create.
_Avoid_: product tag, UPC as a generic term

**Reader**:
The hardware a scan came in through — the camera or NFC. A different axis from
the carrier: the camera reads both labels and barcodes, so the reader narrows
what the carrier can be without deciding it.
_Avoid_: scanner, input, source, carrier (they are not the same thing)

**Carrier**:
Which of the three kinds of code a value was read off — a tag, a label, or a
barcode. The same `nem://t/<uuid>` is byte-identical on a tag and a printed
label, so only the reader knows which it came from, and the carrier is what a
completion records as its source.
_Avoid_: kind, medium, source (as a general word), scan type

**Scan**:
Reading a tag, label, or barcode in order to resolve a target.
_Avoid_: tap, read, check-in

**Provisioning**:
Creating a code and binding it to a target — writing a blank tag, generating a
label, or binding an existing barcode.
_Avoid_: pairing, registering, enrolling, setup

### Sync

**Sync**:
Reconciling this device's data with the backend, in both directions. Never a
source of truth — the local database is authoritative and the backend is a
replica.
_Avoid_: replication, backup, cloud

**Backend**:
The Supabase instance a device is pointed at, whether hosted or self-hosted.
Identified by its URL, which is a setting rather than a build-time constant.
_Avoid_: server, cloud, remote, API

**Outbox**:
The set of local rows changed since they were last pushed. A dirty set, not a
log of edits: it names rows, and the push reads each row's current state, so
five offline edits to one row cost one entry.
_Avoid_: queue, pending changes, journal

**Cursor**:
How far a table's pull has reached, as the last `(updated_at, id)` pair seen.
The id is part of it because two rows can share a timestamp.
_Avoid_: watermark, offset, checkpoint, last sync

**Seed**:
Queueing everything already on a device the first time a backend is configured,
so existing history is pushed rather than stranded.
_Avoid_: backfill, initial sync, bootstrap

### Organisation and notification

**Category**:
A user-defined grouping that cuts across targets — kitchen, car, admin.
_Avoid_: tag, label, group, folder

**Snooze**:
Pushing a task's due date forward without recording that the work was done.
Writes no completion — you did not do it, you decided not to do it yet.
_Avoid_: postpone, defer, skip, dismiss

**Archive**:
Retiring a task so it leaves the due list while keeping its completion history.
Its schedule keeps running underneath, so a restored task returns overdue rather
than pretending the gap did not happen.
_Avoid_: delete, hide, disable, deactivate

**Reference photo**:
An image attached to a task showing what the work involves. Never attached to a
completion.
_Avoid_: attachment, evidence photo

**Digest**:
The single daily notification listing everything due.
_Avoid_: summary, daily reminder, roundup

**Reminder**:
A notification for one specific task, at a time chosen for that task.
_Avoid_: alert, alarm, unqualified "notification"
